# Спецификация: Inside Bar Breakout (1h) + 4h-контекст

> Статус: черновик для обсуждения и проверки на данных.
> Периоды проверки: март–май 2026 и июнь–сентябрь 2026 (оба с первого прогона,
> чтобы исключить in-sample подгонку).
> Дата: 2026-09-08

---

## 1. Концепция

**Вход** — по пробою сжатия волатильности (Inside Bar консолидация) на 1h-свечах.
**Контекст** — 4h-тренд (EMA50) используется ТОЛЬКО для классификации сделки
(continuation/reversal/flat) и записи в CSV, НЕ как фильтр входа на первой итерации.
**Выход** — на первой итерации фиксированный: SL за диапазоном консолидации,
TP = 2×SL. Подключение S/R-уровней — отдельный следующий шаг.

Паттерн и вход живут на **1h** (свечи завершены каждый час → объективный ранний
вход). 4h-данные используются только как контекст на момент начала консолидации.

---

## 2. Определение паттерна (детектор на 1h)

### 2.1 Inside Bar (IB)

Свеча i является IB относительно свечи i-1:

```
high[i] < high[i-1]  И  low[i] > low[i-1]
```

(строго внутри диапазона предыдущей свечи)

### 2.2 Консолидация

Последовательность: **Mother Bar (MB)** + **от 2 до 5 IB подряд** после неё.

```
MB, IB1, IB2, ..., IBn     где 2 <= n <= 5
```

- Каждый IB — внутри предыдущей свечи (определение 2.1).
- MB — свеча непосредственно перед IB1 (не обязательно самая большая; фильтр
  размера MB НЕ применяется на первой итерации — калибруется потом).
- Свечи в консолидации идут подряд, без пропусков по времени.
- «Возраст» консолидации: от начала MB до последнего IB — не более 24 1h-свечей.

### 2.3 Диапазон консолидации

Пробиваемый диапазон — максимум/минимум по ВСЕЙ консолидации (MB + IB):

```
consolidation_high = max(high[MB .. IBn])
consolidation_low  = min(low[MB .. IBn])
```

### 2.4 Детекция пробоя (вход)

Пробой считается **на закрытии 1h-свечи** (не по ходу, не intrabar):

```
LONG:  close[i] > consolidation_high
SHORT: close[i] < consolidation_low
```

- Свеча пробоя i идёт **сразу после** IBn (не внутри консолидации).
- Если close[i] внутри диапазона — пробоя нет, паттерн «устарел» и больше не
  рассматривается (консолидация завершилась без пробоя).

### 2.5 Подтверждение объёмом

На 1h-свече пробоя:

```
volume[i] >= volume_ma20(1h)[i] * 1.5
```

volume_ma20 — скользящее среднее объёма за 20 свечей ДО i (не включая i).

## 3. Классификация сделки (метка в CSV, НЕ фильтр)

На момент начала MB (1h-свеча MB) берём 4h-контекст:

### 3.1 Привязка 1h ↔ 4h (без lookahead)

```python
t_mb_start = df_1h.index[i_mb]                # время начала MB
idx_4h = df_4h.index.searchsorted(t_mb_start, side="left") - 1
# idx_4h — последняя 4h-свеча, закрытая строго ДО начала MB
```

### 3.2 Наклон EMA50(4h)

```python
ema_before   = EMA50_4h[idx_4h - 10]          # ~40h до консолидации
ema_at_start = EMA50_4h[idx_4h]
ema_slope_pct = (ema_at_start - ema_before) / ema_before * 100
```

### 3.3 Тип

```python
if ema_slope_pct > +0.5:   uptrend
elif ema_slope_pct < -0.5: downtrend
else:                      flat

LONG  пробой + uptrend   → continuation
SHORT пробой + downtrend → continuation
LONG  пробой + downtrend → reversal
SHORT пробой + uptrend   → reversal
(любой пробой) + flat    → flat
```

### 3.4 Позиция консолидации в диапазоне

```python
lo = min(low за последние 100 1h-свечей, включая MB)
hi = max(high за последние 100 1h-свечей, включая MB)
mid_cons = (consolidation_high + consolidation_low) / 2
rel = (mid_cons - lo) / (hi - lo)             # 0..1

lower_half: rel < 0.33
middle:     0.33 <= rel <= 0.66
upper_half: rel > 0.66
```

## 4. Уровни сделки (первая итерация)

```
LONG:
  entry = close[i_breakout]          # закрытие пробойной свечи
  SL    = consolidation_low
  TP    = entry + 2 * (entry - SL)

SHORT:
  entry = close[i_breakout]
  SL    = consolidation_high
  TP    = entry - 2 * (SL - entry)
```

- Sizing: как в текущем движке — fixed_risk_usd / (entry × SL%).
- Комиссия: commission_pct (0.05%), вычитается из PnL.
- Одна позиция за раз на символ.

## 8. Принятые решения по открытым вопросам (2026-09-08)

Все три решены по принципу «логируй и смотри в данные, не фильтруй вслепую».

### 8.1 Длинная тень обратно на пробойной свече → БЕЗ фильтра, логировать

Вход по простому правилу (close за диапазоном). Дополнительные метаколонки:
```python
breakout_candle_body_size = abs(close - open) / (high - low)   # если high==low → 0
close_position_in_candle  = (close - low) / (high - low)        # 0..1
```
После прогона смотрим: сделки с body_size < 0.3 — если winrate сильно ниже
среднего, вводим фильтр.

### 8.2 Несколько пробойных свечей подряд → вход на ПЕРВОЙ, логировать серию

Серия = свечи подряд ПОСЛЕ IBn, каждая с close за диапазоном в одну сторону.
Входим на первой. `breakout_series_length` считается ретроспективно (пост-фактум
метрика для анализа): сколько свечей подряд пробило до первой, вернувшейся внутрь
диапазона. Метаколонки:
```python
breakout_series_length    # int
breakout_is_first_in_series  # True (всегда в первой итерации)
```

### 8.3 Повторный вход после SL → НЕТ, одна консолидация = один вход

Консолидация помечается использованной после первого входа. Новая консолидация =
новая MB + новая серия IB, начинающаяся после закрытия сделки. Это не мартингейл.
Повторный вход по той же консолидации запрещён.

## 9. Открытые вопросы (закрыты, см. раздел 8)

1. Вход при длинной тени обратно — решено: без фильтра, логировать (8.1).
2. Серия пробойных свечей — решено: вход на первой, логировать длину (8.2).
3. Повторный вход после SL — решено: запрещён на той же консолидации (8.3).
